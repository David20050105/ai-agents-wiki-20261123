AI Agents 入門 Wiki

AI Agent 是能根據目標與觀察，動態選擇下一步及工具的 AI 系統。本 Wiki 介紹它的基本組件、運作方式與檢查條件。

1. 什麼是 AI Agent？

本 Wiki 採用實務上的定義：Agent 讓 LLM 依目標與觀察，動態選擇下一步及工具；自主程度可以不同。 [S01、S03]

Workflow 依事先定義的路徑執行。相同任務可能用 workflow 完成，也可能需要 Agent 的動態決策。 [S01、S03]

例子：一般聊天給你找資料的方法；研究 Agent 可選擇查詢、閱讀結果、發現缺口後再查。這只是比較情境，非所有聊天產品都沒有工具。

2. Agent 的決策與行動迴圈

ReAct 展示推理與行動交錯的方式：根據當前資訊選擇行動，取得外部觀察，再調整下一步。 [S02]

例子：選擇行動 → 工具執行 → 讀取觀察 → 檢查目標。滿足目標就停止；最多 3 次仍不足就回報缺口。3 次是本案例的限制，不是論文規定。

3. 模型如何使用工具？

工具有明確的輸入與輸出。模型提出工具名稱與參數，執行環境呼叫函式，再把結果交回後續流程。 [S06]

例子：search_wiki(query="短期記憶") 是結構化請求。系統回傳概念頁與來源；沒有命中時應回報未找到，而非補寫事實。

4. 狀態、記憶與 Wiki

短期記憶追蹤同一對話中的狀態；長期記憶保存跨對話可用的資訊，需由系統管理保存與取用。 [S04]

例子：Wiki 是持久保存的外部知識檔案；查詢時才取出相關頁面。這不是重新訓練模型，也不是每個 Agent 都必備完整長期記憶。

5. 工具結果與人工檢查

Graph 可暫停等待外部輸入後繼續，適合設計人工審核節點。 [S05]

設計建議：檢查工具輸出，再將資料寫入結論。 [S06]

例子：資料不足可重查；寄出郵件或更改資料前先讓人檢查。達到重試上限就停止並說明缺少哪些證據。

6. Workflow 與 Graph 怎麼選？

任務步驟已知時可先用固定 workflow；需要依新觀察選擇下一步時，再考慮動態 Agent。 [S01、S03]

參考資料與重點

  1. S01 · Building effective agents

    本文以控制流程區分 workflow 與 Agent：前者由預先寫好的路徑安排，後者讓模型動態決定流程與工具使用。建議先用簡單方案，確有需要再增加自主程度。

  2. S02 · ReAct: Synergizing Reasoning and Acting in Language Models

    ReAct 研究交錯安排推理與行動，透過與外部環境互動取得觀察，再更新計畫。它提供理解 Agent 迴圈的例子；論文的特定實驗成果不能延伸成所有 Agent 都可靠。

  3. S03 · Workflows and agents

    文件對照固定 workflow 與動態 Agent，並介紹工具呼叫、結構化輸出、短期記憶等擴充。Graph 可用節點表達工作，用連線表達先後或分支。

  4. S04 · Memory overview

    短期記憶維持同一對話的狀態；長期記憶保存跨對話可取用的資料。儲存、摘要與檢索由應用程式設計，歷史內容也可能過時或超出上下文範圍。

  5. S05 · Interrupts

    Interrupt 可在指定位置暫停 graph，等待外部輸入再繼續；持久化狀態讓執行可以恢復。這可用於人工審核、補充資訊與批准動作。

  6. S06 · Tools

    工具是有清楚輸入與輸出的可呼叫函式，可查詢資料、執行程式或採取外部行動。模型依上下文提出工具選擇與參數，系統負責執行並回傳結果。
