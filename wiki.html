W01 / Agent · 定義 · 自主 · 比較

什麼是 AI Agent？

C01 本 Wiki 採用實務上的定義：Agent 讓 LLM 依目標與觀察，動態選擇下一步及工具；自主程度可以不同。

C02 Workflow 依事先定義的路徑執行。相同任務可能用 workflow 完成，也可能需要 Agent 的動態決策。

教學例

教學例：一般聊天給你找資料的方法；研究 Agent 可選擇查詢、閱讀結果、發現缺口後再查。這只是比較情境，非所有聊天產品都沒有工具。

W02 / loop · ReAct · 迴圈 · 觀察 · 停止

Agent 的決策與行動迴圈

C03 ReAct 展示推理與行動交錯的方式：根據當前資訊選擇行動，取得外部觀察，再調整下一步。

教學例

教學設計：選擇行動 → 工具執行 → 讀取觀察 → 檢查目標。滿足目標就停止；最多 3 次仍不足就回報缺口。3 次是本案例的限制，不是論文規定。

W03 / 工具 · tool · 參數 · 執行 · 查詢

模型如何使用工具？

C04 工具有明確的輸入與輸出。模型提出工具名稱與參數，執行環境呼叫函式，再把結果交回後續流程。

教學例

教學例：search_wiki(query="短期記憶") 是結構化請求。系統回傳概念頁與來源；沒有命中時應回報未找到，而非補寫事實。

W04 / 記憶 · memory · 狀態 · Wiki · 知識庫

狀態、記憶與 Wiki

C05 短期記憶追蹤同一對話中的狀態；長期記憶保存跨對話可用的資訊，需由系統管理保存與取用。

教學例

本作業的 Wiki 是持久保存的外部知識檔案；查詢時才取出相關頁面。這不是重新訓練模型，也不是每個 Agent 都必備完整長期記憶。

W05 / 檢查 · 人工 · 核准 · 停止 · 錯誤

工具結果與人工檢查

C06 Graph 可暫停等待外部輸入後繼續，適合設計人工審核節點。

C07 設計建議：檢查工具輸出，再將資料寫入結論。

教學例

本案例規則：資料不足可重查；寄出郵件或更改資料前先讓人檢查。達到重試上限就停止並說明缺少哪些證據。
