每一關看什麼，錯了回哪裡？

節點輸入／產物檢查回退路線
取得／ingest原網址、章節、摘錄同一來源一個 ID；至少 5 篇回到該篇證據卡
Wiki／查詢主張、交叉連結、檢索分數至少 3 個相關頁；六個子題有依據補檢索或停止
逐頁稿Wiki ID、主張 ID、來源 ID每頁有引用；例子與事實區分只修該頁或該 Wiki
HTML保存的逐頁稿渲染不新增知識文字內容錯回稿；樣式錯修 CSS
瀏覽器HTML／CSS／JS切頁、測驗、搜尋、不同寬度局部修正後重檢

哪些步驟會重複？

來源轉址或欄位缺漏時，只整理該篇筆記；缺子題時補查 Wiki；逐頁稿引用或內容錯誤時，只修該頁；HTML 溢出時先確認是否文字過多，再退回逐頁稿或修 CSS。每個局部修正最多 2 輪，全案最多 3 輪；仍未通過就停止並留下缺口報告。

為什麼這樣設計？

在排版前確認來源與子題，避免花時間美化沒有根據的內容。用來源 ID → 主張 ID → Wiki ID → 簡報頁碼保存連結，使修正可定位。渲染只使用逐頁稿，防止排版時悄悄改變說法。

五項 loop 規格

目標
以 Wiki 為來源，讓初學者理解 AI Agents。
限制
不補寫未入 Wiki 的外部事實；不把教學模擬說成真實執行。
完成標準
至少 5 篇 ingest、12 頁簡報、逐頁引用、來源覆蓋、可操作 HTML、實際報告。
驗證
程式結構檢查、逐條文意對照、瀏覽器操作與畫面檢查。
停止規則
資料不足或達重試上限則停止；全部通過則交付。
