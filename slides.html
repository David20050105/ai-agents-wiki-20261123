一個 Agent 系統的基本組件

  • 目標要交出什麼，怎樣算完成
  • 模型理解情境並選擇下一步
  • 工具查詢資料或執行外部動作
  • 狀態保留進度、證據與缺口
  • 控制規則限制權限、重試與停止

模型提出行動，執行環境落實行動。

工具呼叫如何真正發生？

search_documents(query="校園節能", limit=3)
{ status: "ok", documents: ["A", "B"] }

提出呼叫，不等於執行成功。

找到資料，不等於證據已足夠。

下面的搜尋請求與回傳值是教學示意。回傳兩篇文件，表示工具確實找到兩篇；若目標需要三篇，就還不能直接宣布完成。若回傳的是逾時或權限錯誤，也不能把錯誤訊息包裝成正常資料。

Workflow、Graph 與常見控制模式

  • 串接前一步的結果交給下一步
  • 路由依問題類型選擇處理方式
  • 平行獨立子題可同時處理
  • 檢查與修正依明確標準局部重做

Graph 表達步驟、分支與回退。

Loop 讓某段流程依回饋重複執行。

人工介入、權限與工具邊界

  • 資料不足詢問使用者或補查
  • 外部動作執行前核對對象與內容
  • 權限不符停止該動作並回報
  • 可疑指令將外部文字視為資料

自主決策不等於無限制權限。
